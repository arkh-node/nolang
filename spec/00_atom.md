# nolang spec 00 — Atom

*Первый камень грамматики. Roadmap `[ ] grammar (value vs judgment)`.
Атом НЕ декларируется — он выводится из фундамента (helpbook Obj0 → токен → атом) и получает форму (s-expr)
и семантику (денотация). Метод: снизу (metarung), гейт «выводится, а не приделывается».*

## 1. Деривация (почему атом такой, а не иной)

Из фундамента (`helpbook/02/001`, `mentor/NOL_GENESIS.md`):
- **токен** — форма, узнаваемая снова («это она снова»). Голое. Носитель отличия. У nolang это **value**.
- **атом** — токен, занявший **место в отношении** («где стоит и в каком отношении»); «формула удержания чего-то в чём-то».
  У nolang это **judgment**: отношение над values, `(isa tomato vegetable)`.
- закон genesis: **«атом без источника — дефект»** → judgment обязан нести **trace** (источник).
- закон nolang: судить = нести **`(f,c)`** (насколько держится, насколько уверены). Уверенность — не украшение.

Вывод: **атом = отношение над токенами + `(f,c)` + trace.** Ни одного лишнего слагаемого; убери любое — атом перестаёт быть собой:
без отношения это token (value); без `(f,c)` это булев факт (украденная определённость); без trace это дефект (genesis).

## 2. Форма (синтаксис — поздняя награда, s-expr, homoiconic)

```
value     := symbol | string | path              ; голое, без истины (токен)
relation  := symbol                              ; имя отношения (isa, safe, part-of, …)
judgment  := (relation value*)                   ; атом БЕЗ ещё приписанной истины
atom      := judgment @ (f . c) << trace         ; атом = judgment + (f,c) + источник
```

Конкретная запись (читается как s-expr, дисциплина Lisp — форма ближе к структуре):
```
(subject ари)                                           ; judgment: субъект ли Ари (форма отношения)
((subject ари) (0.5 . 0.4) "zenodo:21288590")           ; ATOM: judgment + (f . c) + trace — статус неопределён, c<1
((safe migration) (0.9 . 0.7) "ci:run-4412")            ; ATOM инженерный — ведёт к gate/revgate
```
`value` и `judgment` **различимы синтаксически** (value — не список / не начинается с отношения; judgment — список).
Это и есть закрытие roadmap-пункта «value vs judgment».

> Имя в реализации: в Lisp примитив зовётся `natom` — имя `atom` занято Common Lisp (встроенный предикат,
> пакет заблокирован). Концептуально это **атом** (термин книги); `natom` — вынужденное реализационное имя.

## 3. Семантика (денотация — что атом ЗНАЧИТ)

Денотация атома = тройка **⟦atom⟧ = (relation-applied, graded-truth, provenance)**:
- **relation-applied** — отношение, применённое к values (что утверждается).
- **graded-truth** — `(f . c)`: `f` ∈ [0,1] насколько держится; `c` ∈ [0,1) насколько уверены. **`c < 1` всегда** (Эйн-Соф/AIKR: одно свидетельство ≠ полная уверенность; `c=1` синтаксически недопустимо).
- **provenance** — trace: откуда. Пусто → **дефект** (genesis-закон), денотация не определена.

Инвариант атома (что удерживается через любой ход): **triple (relation, values, trace) фиксирован; (f,c) ревизуем.**
Это триада в деле: форма (relation+values) · отношение (утверждение) · удержание (trace держит атом как «тот же» через ревизию `(f,c)`).

## 4. Чего здесь ПОКА НЕТ (честная граница камня)
- capability effects (как `(f,c)` гейтит класс действия) — следующий камень (`spec/01_gate.md`).
- трёхзначный if, evaluator, ilan fold/sprout — выше по метарунгу.
- NARS-подложка для вывода — отдельный слой.
Этот камень даёт ровно: **различить value от judgment, собрать атом с `(f,c)`+trace, вычислить его денотацию, отвергнуть дефект.**

## 5. Гейт (проверка, что это не замок Хаула)
Каждое слагаемое атома выведено: отношение ← атом-книги (место в отношении); `(f,c)` ← nolang-тезис; trace ← genesis-закон.
Ничего не приделано. Если добавляем поле в атом — оно обязано иметь такую же деривацию из фундамента.
