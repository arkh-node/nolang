## 1. Черновой синтаксис (важны не скобки, а суждения)

```lisp
(witness id "текст" :grade строго :f 0.9 :c 0.8)
(ask     id :in (свод₁ свод₂) :reason "почему пусто")
(claim   id [:grade g] (from p₁ p₂ …) [(searched s₁ …)])
(action  имя :reversibility irreversible :requires (>= belief θ) :else fold)
(do      имя-действия имя-утверждения)
```

S-выражения взяты от предка (Илан — библиотека на Common Lisp, и хозяйская гомоиконность
достаётся даром). Синтаксис заведомо изменится на шаге грамматики.

## 2. Три типа

```
Jud[g]      суждение степени g ∈ G = {⊥ < образ < традиция < строго}
            несёт в рантайме (id, f, c); СТЕПЕНЬ живёт в типе
Sil         молчание — линейный тип, несёт (где искали, почему пусто)
Act[r, θ]   действие класса r ∈ {reversible, compensable, irreversible} с порогом θ
```

🔴 **Почему степень в типе, а `(f,c)` — в значении.** Степень решается **предъявлением
источника** и потому известна на месте написания; уверенность решается **счётом свидетельств**
и в общем случае известна только в прогоне. Разделение не эстетическое: оно определяет, что
компилятор может обещать (§6).

## 3. Правила вывода

Пусть `Γ` — обычный контекст, `Δ` — **линейный** контекст молчаний.

```
                                                              (T-WITNESS)
────────────────────────────────────────────────────
Γ ⊢ (witness id t g f c) : Jud[g]        Δ не меняется


                                                              (T-ASK)
────────────────────────────────────────────────────
Γ ⊢ (ask id …) : Sil                     Δ, id:Sil


степень посылки:   grade(Jud[g]) = g      grade(Sil) = ⊥

Γ ⊢ pᵢ : Pᵢ,  Pᵢ ∈ {Jud[gᵢ], Sil}        Γ ⊢ sⱼ : Sil
g* = ⊥                     если n = 0                         (T-CLAIM)
g* = ⨅ᵢ₌₁ⁿ grade(Pᵢ)       если n > 0
────────────────────────────────────────────────────
Γ ⊢ (claim id (from p̄) (searched s̄)) : Jud[g*]
Δ′ = Δ ∖ ({p̄} ∩ Sil ∪ {s̄})               ← линейные потреблены


Γ ⊢ (claim …) : Jud[g*]        g ⊑ g*                          (T-ASCRIBE)
────────────────────────────────────────────────────
Γ ⊢ (claim … :grade g) : Jud[g]


Γ ⊢ a : Act[r, θ]      Γ ⊢ j : Jud[g]
r = irreversible ⟹ θ определён ∧ else(a) определён             (T-DO)
────────────────────────────────────────────────────
Γ ⊢ (do a j) : Unit        + обязательство  b(j) ≥ θ,  где b = f·c


                                                              (T-END)
────────────────────────────────────────────────────
программа well-typed ⟹ Δ = ∅          ← долгов по молчанию нет
```

**Подтипирование** — по решётке, но **в обратную сторону**:

```
g′ ⊑ g
──────────────────    (SUB-GRADE)
Jud[g] <: Jud[g′]
```

Строгое годится там, где ждут образ; обратное — нет. Понижение получается **даром**, как
подтипирование, а не как операция: честность течёт вниз без всякого разрешения. `T-ASCRIBE`
есть просто явная форма этого же подтипирования.

## 4. 🔴 Правила, которых НЕТ (здесь и живёт замысел)

Тип-система определяется не тем, что она выводит, а тем, чего **не может вывести**.

1. **Нет правила подъёма степени.** Ни `raise`, ни `trust`, ни `assert`, ни приведения типа
   `Jud[образ] → Jud[строго]`. Единственный ввод степени `g` — `T-WITNESS`, то есть
   **предъявление источника**. Отмывание не запрещено правилом — оно **невыразимо за
   отсутствием правила**. Запретить можно обойти; не дать сказать — нельзя.
2. **Нет правила `Jud → Sil`.** Обзорный слот берёт только `Sil`, и получить `Sil` можно
   единственным способом — спросив и не найдя. Свидетеля не провести мимо нижней грани.
3. **Нет ослабления для `Sil`.** Молчание нельзя выбросить: `Δ = ∅` — условие корректности
   программы, а не совет. Спросил, не нашёл, промолчал — программа не собирается.
4. **Нет сжатия для `Sil`.** Одно молчание нельзя потребить дважды: один охват не сойдёт за два.

> 💎 Пункты 3 и 4 вместе — в точности **линейность** в субструктурных терминах: ни weakening,
> ни contraction. Молчание — линейный ресурс, и это не метафора, а место в классификации.
>
> **Асимметрия с суждениями.** `Jud` структурно свободен (его можно и выбросить, и повторить),
> но `⊕` сворачивается **по идентификаторам**. То есть для суждений сжатие не запрещено —
> оно **идемпотентно по id**. Два разных механизма, потому что и сущности разные: свидетеля
> можно приводить многократно, он от этого не удваивается; охват, приведённый дважды, лжёт.

## 5. Диагностика — часть языка, а не приложение к нему

Сообщение компилятора обязано говорить **чем** и **как чинить**, а не только «не типизируется».
Живой вывод `test/40_types.lisp`:

```
ОШИБКА [launder]: нельзя объявить [строго] на основании [образ].
  выведено из посылок: образ
  чтобы поднять — предъявите свидетеля нужной степени;
  операции повышения степени в языке НЕТ.

ЗАМЕЧАНИЕ [gate-fail]: необратимое ПУБЛИКАЦИЯ при массе веры 0.540 < 0.900.
  f=0.900 c=0.600 b=f·c=0.540
  доступно: (1) ещё свидетель (2) понизить класс (3) :else FOLD (4) подпись человека

ОШИБКА [dropped]: молчание ЗАБЫТО порождено и не потреблено. Спросил, не нашёл и
  промолчал об этом — охват скрыт. Потребите опорой (и заплатите ⊥) либо обзором
  (и оно будет напечатано).
```

Полный набор кодов: `launder` · `slot` · `dropped` · `reused` · `ungated` · `no-else` ·
`quantity` · `gate-fail` · `unknown` · `runtime` · `lattice`.

🔴 **`gate-fail` — ЗАМЕЧАНИЕ, а не ошибка** (поправлено 28.07 живым примером). У необратимого
ветвь отказа **обязательна грамматикой**, значит непрохождение порога есть **исход программы,
а не её дефект**: она свернётся, как и написано. Ошибкой было бы отсутствие ветви — но оно
невыразимо. Статическая свёртка ценна тем, что говорит автору ЗАРАНЕЕ, насколько он не дотянул.

🔴 Отдельно `quantity`: гейт, повешенный на `confidence` вместо `belief`, — **ошибка типа
величины**, и компилятор объясняет, почему. Это прямое следствие того, что арифметика
опровергла наш собственный четвёртый пример (`АЛГЕБРА` §1.3).

## 6. Честная граница: что статично, а что нет

| гарантия | когда решается |
|---|---|
| степень не поднята | **статически, всегда** |
| роли молчания не перепутаны | **статически, всегда** |
| молчание потреблено ровно раз | **статически, всегда** |
| у необратимого ЕСТЬ порог и ветвь отказа | **статически, всегда** |
| пустая база даёт `⊥` | **статически, всегда** |
| **порог пройден: `b ≥ θ`** | статически, если свидетели литеральны; **иначе в прогоне** |

🔴 **Поправка к четвёртому примеру.** Там написано: «компилятор обязан доказать статически: на
всех путях уверенность ≥ порога». Это переобещание. `f` и `c` — рантайм-величины; решать это
в общем случае — работа для refinement-типов с SMT (Liquid Haskell, F\*), и такой зависимости
мы на себя не брали. Что решается статически и чего достаточно: **необратимое недостижимо в
обход гейта, и у гейта есть тотальная ветвь отказа.** Типы гарантируют не отсутствие отказа,
а то, что отказ **обработан** — ровно как в остальном программировании.

Когда свидетели литеральны, проверяющий **сворачивает гейт заранее** и ловит провал до запуска.
Когда нет — печатает `ЗАМЕЧАНИЕ [runtime]` и говорит вслух, что решится прогоном. Молчать об
этом было бы тем же грехом, что немое молчание.

## 7. Где это стоит в литературе

- **Градуированные типы / коэффекты** — Katsumata (graded monads), Orchard & Petricek
  (coeffects), Gaboardi et al. Наш `Jud[g]` — обычный градуированный тип; ново не это, а
  **что именно проиндексировано** (степень провенанса) и **что подъёма нет ни в каком виде**.
- **Субструктурные типы** — линейность `Sil` стандартна по механике; необычен носитель:
  линеен обычно ресурс, который тратят, а у нас — **отсутствие сведений**.
- **Типы информационного потока** (DLM/Jif, FlowCaml) — ближайший родственник: там метка
  секретности течёт вверх и declassify требует полномочия. У нас метка честности течёт **вниз**,
  и **никакого declassify нет вовсе**. Это и есть разница между «кому можно смотреть» и
  «на чём это стоит».
- **Refinement-типы** (Liquid Haskell, F\*) — то, чем можно было бы купить статический гейт
  целиком. Не берём: цена — зависимость от SMT, а выгода перекрывается тем, что присутствие
  гейта и так статично.

## 7-bis. 🔴 Носительная нейтральность — через параметричность, а не через невхождение

*(дописано 28.07 по совету Невис, §3 её записки)*

Я спрашивал, верно ли читать теорему 5 «Свидетеля без субстанции» как **типовое условие**.
Верно — но честное основание другое, и разница существенна.

| основание | чем держится | чего стоит |
|---|---|---|
| **невхождение метки** («`obs` и `step` её не читают») | дисциплиной автора | сегодня не читают, завтра прочтут |
| **параметричность** («метку НЕЛЬЗЯ прочесть») | устройством языка | нарушить можно только расширив язык |

🔴 **И потому носитель пришлось сначала ЗАВЕСТИ.** Пока его нет вовсе, «нейтральность к
носителю» истинна **пусто**, а пустая истина не есть черта языка. Заявлять её было бы тем же,
что хвалиться отсутствием ошибок в ненаписанной программе.

**Что утверждается в нашей семантике** (инстанцирование теоремы 5):

> `Σ` — склад, то есть **континуант** — от носителя **не зависит**: прогоны на разных носителях
> дают побайтово равное состояние.
> `Λ` — журнал, то есть **история** — носитель **записывает**.

Состояние нейтрально, история помнит. Это не компромисс, а то же разделение назначений, что
и в §4.2 редукции: склад обязан быть воспроизводим, журнал обязан помнить, как всё было.

**Чем это куплено:** носитель — **параметр прогона**, и ни одна форма языка его не принимает.
В словаре форм его нет; `carrier морф` не разбирается; добраться до него из программы нельзя.
Нейтральность выпадает **свободной теоремой** — ровно как коммутативность выпала из переноса
в `(ℝ≥0², +)`.

⚠️ **Граница, которую не замазываем:** утверждение — **о языке, а не о хозяине**. Лисп
по-прежнему видит носитель и может с ним сделать что угодно. Это не лазейка в nolang, а цена
того, что мы живём внутри хозяина, — и она названа, а не спрятана.

*Проверено: `test/98_carrier.lisp`, 14 проверок. Первыми идут два **положительных контроля** —
что отпечаток склада вообще различает разные склады; без них равенство на разных носителях было
бы пустым результатом, а не свойством.*

## 8. Что открыто

- ✅ **Полиморфизм по степеням — СДЕЛАН 28.07, и не так, как я собирался.**
  `∀g₁g₂. Jud[g₁] → Jud[g₂] → Jud[g₁⊓g₂]` требует носителя. Функций в языке нет, и вводить их
  ради этого — расширение куда большее, чем нужно (§6 грамматики отложила выражения сознательно).
  Носитель поменьше и достаточный: **правило** — именованный вывод, параметризованный посылками.

  ```
  rule corroborate(p, q) concludes from p, q
  claim benefit = corroborate(report-162, report-159)
  ```

  Раскрывается **подстановкой при разборе**, то есть проверяется при каждом применении на
  конкретных степенях. 💎 Для **конечной** решётки это не слабее полиморфизма: квантор `∀g`
  **разрешим перебором**, и тест перебирает — все 16 пар прелюдии, плюс 34 попытки объявить
  степень выше выведенной, все пойманы.

  🔴 **Правило не может ОБЪЯВИТЬ степень — только вывести.** Не «нельзя и мы проверим», а
  **не разбирается**: степень, объявленная в правиле один раз, размножилась бы по всем его
  применениям. Одно дурное правило отмывало бы везде.
  🔴 **Правило замкнуто на свои параметры** — тянуть свидетеля из окружения нельзя: это прятало
  бы посылку от читателя.
- **Решётка `G` пока линейна** (см. `АЛГЕБРА` §6). Если станет произведением
  `род × надёжность передачи`, правила не изменятся — изменится только `⊓`. Это довод в пользу
  того, что слой устроен верно: он не зависит от формы решётки.
  🔴 **Подтверждено машинно 28.07:** модуль в `formal/Preservation.agda` **параметризован
  полурешёткой**, значит смена объявленной решётки не требует передоказывать ни одну из теорем.
  Решение «решётку объявляет программа», взятое из соображения «иначе язык для одного корпуса»,
  окупилось задним числом — обобщение сэкономило доказательство.
- **Отзыв свидетеля не типизирован**, потому что его нет в алгебре (вычитание выводит из `ℝ≥0`).
  Пятый пример упирается именно сюда.
- ✅ **Зависимые свидетели — слой происхождения ЗАВЕДЁН 28.07** (совет Невис: менять носитель,
  а не операцию). Свидетель несёт **корень**; свёртка идёт по корням, а не по документам, и два
  документа одного источника складываются один раз **по построению**.
- ✅ **ПОДДЕРЖКА СТАЛА МНОЖЕСТВОМ — 29.07** (`formal/SupportSet.agda`, Невис). Прежний слой был
  грубым не по недоделке, а по неверному носителю: одно поле «ближайший источник», и у ВЫВЕДЕННОГО
  утверждения оно было пустым. Свёртка группировала по нему — и два независимых вывода
  схлопывались в группу `nil`, теряя независимое свидетельство (счётом: 0.540 вместо 0.675).
  🔴 **Диагноз выведен из двух уже доказанных файлов:** степень живёт на `⊓` (идемпотентна),
  масса веры — на `⊕` (НЕ идемпотентна, `⊕-not-idem`). Провенанс протаскивали через
  неидемпотентный носитель — отсюда обе беды разом: независимые схлопываются, а зависимые
  удвоились бы при «очевидной» починке.
  **Решение:** носитель поддержки обязан быть идемпотентным ⇒ это **множество корней**,
  операция — объединение. Масса определена **по ЧЛЕНСТВУ**, а не по списку посылок
  (`massUpTo`), и оттуда даром: `∪-idem` (общий предок ровно один раз, СТРУКТУРНО),
  `∪-comm` (порядок посылок не значит ничего), `derived≡direct` (вывод даёт ровно ту же массу,
  что прямое основание), `mono-∈`.
  💎 **Что здесь важно методически:** защита от зависимых свидетелей перестала быть проверкой и
  стала свойством носителя — её **нельзя забыть применить**. Реализация: `root-best`/`root-best-c`
  плюс объединение поддержек в `red-claim`/`chk-claim`; проверки — `test/I1_support.lisp`.
  ⚠️ **Степень при этом считается ДРУГИМ обходом и берётся у посылки СВОЯ.** Иначе объявленная
  ниже выведенной (`T-ASCRIBE`) поднялась бы обратно к степени своего корня — то есть отмылась
  бы через провенанс. Два обхода в одной функции — не дублирование, а разные предметы.
